## 写笔记的约定

- **命名**：用话题命名，不带日期、不带编号。文件名就是读者会搜的词。
- **头部**：`日期` / `状态`（草案、已定、已落地）/ `结论`，让只想扫一眼的人拿到答案。
- **结构**：起因 → 推导（含被推翻的方案和推翻理由）→ 结论 → 遗留。保留「为什么否掉」比保留「最终是什么」更有价值。
- **引用**：代码位置写到 `文件:行号`；标准库结论注明 Go 版本。行号会漂移，版本至少能定位。
- **结论先行**：末尾用「如果只看一行」收束，避免读者翻到最下面才发现重点。
- **遗留**：用 `- [ ]` 列出还没验证的假设、还没补的测试、将来可能重开的话题。
